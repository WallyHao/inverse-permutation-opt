# TSP 排列稳态进化算法测试平台搭建计划

文档日期：2026-09-29。状态：设计与实施计划，尚未实现平台。

## 1. 项目任务与平台定位

本项目研究稳态进化算法在排列组合优化中的探索与利用机制，以对称旅行商问题（symmetric TSP）为主要实验对象。总体问题是：伪布尔优化中关于逆向选择压力的理论与经验发现，在排列编码、交叉重组及精英替换共同作用下是否仍然成立，其适用条件与失效边界是什么？这里的 inverse 指逆向选择压力，不是将排列取逆作为默认表示。

当前具体研究阶段已由交叉选型文档收敛为：固定 `(μ+1)` 稳态 GA 的其余组成，比较 PMX、OX、ERX，以及根据父代边差异选择 OX/ERX 的项目方法 SAX。平台应首先支撑这一受控实验，随后支持选择压力、第二父代策略和局部搜索的交互研究。平台开发者的任务是提供可验证、可比较、可复现的实验基础设施；算法是否更优应由实验检验，不能成为平台验收的前提。

### 1.2 研究问题与可观测证据

| 研究问题 | 控制与处理因素 | 平台必须提供的证据 |
| --- | --- | --- |
| RQ1：不同结构保留方式如何影响搜索？ | 固定 GA，仅改变 PMX/OX/ERX/SAX | 固定预算 gap、收敛轨迹、目标命中时间、边与位置保留率 |
| RQ2：SAX 的结构信号是否有用？ | SAX 对比固定 OX、ERX 及固定概率混合 | 父代边差异、实际委派频率、效果差异与计算开销 |
| RQ3：选择压力是否改变交叉效果？ | 交叉与 Parent-1 选择组成因子实验 | 分层效果、交互差异、种群边多样性与克隆比例 |
| RQ4：结论对实验条件是否稳健？ | 分别改变第二父代策略、局部搜索、规模 | 明确预算口径下的重复实验与敏感性分析 |

RQ1 是首个正式实验；RQ2 是解释 SAX 机制所需的消融；RQ3/RQ4 是后续扩展。SAX 当前是项目提出的方法，不预设新颖性或优势。实验证据不能替代排列空间上的运行时间定理。

## 2. IOHexperimenter 的借鉴范围

IOHexperimenter 将问题求值、问题集合、实验编排和日志组织为可组合组件，并允许控制记录粒度；这些设计适合本项目参考。[IOHexperimenter 论文](https://arxiv.org/abs/2111.04077)

其官方接口展示了问题状态、日志绑定、run 重置、静态运行属性和动态属性记录。本平台借鉴这些职责边界，采用自己的排列问题协议。[官方 Python 文档](https://iohprofiler.github.io/IOHexperimenter/python.html)

“无法直接复用”在本计划中的工程含义是：通用问题与日志机制不能直接给出本项目所需的排列合法性、TSPLIB 语义、GA 算子事件、局部搜索预算和机制分析协议；并非断言 IOHexperimenter 技术上不能封装自定义 TSP。第一版不以安装、继承或修改 IOHexperimenter 为必要条件。

| 参考概念 | 本平台对应组件 | 项目特有的设计 |
| --- | --- | --- |
| Problem / State | `TSPProblem` / `EvaluationContext` | 闭合回路、排列合法性、最小化、权威预算台账 |
| Suite | `InstanceRegistry` / `BenchmarkSuite` | 实例文件身份、距离类型、最优值来源；城市数由文件决定 |
| Experiment | `ExperimentSpec` / `Runner` | 算子配置 × 实例 × 重复编号，受控初始种群与独立 run |
| Logger / Trigger | `Observer` / `Trigger` | 改进事件、固定评估检查点、算子与种群诊断 |
| Run attributes | `RunManifest` | 配置、代码、数据、随机数、环境和协议版本 |
| Analyzer output | 本地分析模块与可选导出器 | 原生结果为权威来源；兼容导出作为独立适配层 |

日志触发与属性提取分离，避免观测逻辑侵入算子实现。[官方 logger 文档](https://iohprofiler.github.io/IOHexperimenter/cpp/ioh_logger.html)

后续可支持 IOHanalyzer，但必须针对选定版本完成实际导入测试，不能把任意 CSV 称为兼容格式。其固定预算、固定目标及跨问题汇总的分析思路可作为参考。[IOHanalyzer 论文](https://arxiv.org/abs/2007.03953)

## 3. 范围、实施路线与责任边界

### 3.1 第一版必须完成

1. 支持已声明距离类型的对称 TSP，完成实例校验与最优值溯源。
2. 给出语言无关的单次运行、单后代交叉、求值、预算及观测接口。
3. 提供公共 `(μ+1)` GA 执行框架，接入 OX 后再接入 PMX、ERX、SAX。
4. 支持配对初始化、固定预算、目标命中、批处理及失败追踪。
5. 产出不可混淆的原始日志、汇总表、图和实验清单。
6. 完成正确性、确定性、预算边界和分析流程的验收。

第一版不建设 Web 服务、数据库集群、自动调参系统或通用优化平台。不将 QAP、ATSP、EAX、Lin–Kernighan 和完整混合/层内选择纳入首轮交付；保留扩展接口即可。DSX 可用于后续历史复现，不能用 ERX 冒充 DSX。

### 3.2 技术路线建议

仓库尚未确定实现语言。建议使用 Python 组织配置、批量实验和分析，先提供可审计的参考执行内核；通过 pilot 测量后再决定是否将交叉、距离与局部搜索热路径迁至编译实现。此项是工程建议，不是仓库已有决定。

若算法开发者采用 C++、Rust 等语言，应保持同一协议，通过绑定或单 run 子进程适配；不要在每次求值时进行进程间通信。参考内核和优化内核须用相同固定输入进行差分验证。更换内核后单独记录实现版本，不默认不同语言的 RNG 可以逐步复现。

平台负责人负责问题/预算/日志/编排/分析及协议验收；算法负责人负责算子实现、变体说明及算法级测试；实例名单、复现口径和正式统计假设由研究团队冻结。平台中保留一个简单基准算法，确保验证不依赖全部研究算法同时就绪。

### 3.3 建议目录

以下均为未来结构，本次仅创建本文件。算法代码可在同一包内实现，也可经 `adapters/` 对接团队代码。

```text
src/tsp_perm_ea_bench/
  PLAN.md
  problems/       # TSP 定义、距离、实例加载、排列与边工具
  core/           # 协议、预算、状态、随机流、配置校验
  algorithms/     # 公共稳态框架与基准算法
  operators/      # selection / crossover / mutation / replacement
  observers/      # 事件、触发、持久化、机制指标
  runner/         # 单次运行、任务展开、并行与恢复
  analysis/       # gap、命中、统计、图表与导出
  adapters/       # 外部算法和可选 IOHanalyzer 适配
  cli/            # validate / run / batch / summarize 等入口
```

根级目录只在后续实施时建立。实例原文件依据再分发条件决定是否入库；大型实验产物另存并记录校验和。现有 `output/` 继续用于文档产物，避免混用实验数据与论文 PDF。

## 4. 问题层与基准实例管理

### 4.1 数学定义与表示

对 `n≥3` 的对称 TSP，解为排列 `π∈S_n`，内部城市编号统一为 `0,…,n−1`，保留与原始编号的双向映射。目标为

\[
f(\pi)=\sum_{i=0}^{n-1}d(\pi_i,\pi_{(i+1)\bmod n}),\qquad \min f(\pi).
\]

所有选择与替换均直接使用路径长度：越小越好；逆向锦标赛选择较大长度的个体。避免将“适应度最低”与“路径最短”混为一谈。

无向边表示为 `(min(u,v), max(u,v))`，必须包含首尾闭合边。对称 TSP 的旋转、反向回路具有相同目标和边集；平台只在重复解诊断、归档时使用等价类规范表示，不默认旋转或翻转输入算子的排列。否则会改变 PMX/OX 的位置语义，成为隐藏处理因素。

### 4.2 距离语义

第一版优先支持 `TYPE=TSP`、`EDGE_WEIGHT_TYPE=EUC_2D`，按 TSPLIB 定义逐边取整：`floor(sqrt(dx²+dy²)+0.5)`，不能替换为未取整欧氏长度或语言默认的银行家舍入。扩展 `EXPLICIT` 时逐个声明支持的矩阵格式；未支持的 ATT/GEO 等类型必须明确报错。[TSPLIB95 规范，第 1–2 节](https://comopt.ifi.uni-heidelberg.de/software/TSPLIB95/tsp/tsp95.pdf)

加载时检查维数、节点唯一性、字段完整性、有限数值、非负权重及对称性；拒绝尚未支持的固定边约束。路径总和使用足够宽的整数，浮点仅用于坐标距离计算。对已知参考 tour 重算长度；与登记值不一致时，该实例不得进入正式实验。

### 4.3 实例清单与分层

每个实例登记 `instance_id`、原名、`n`、问题/距离类型、下载来源与日期、文件 SHA-256、解析器版本、参考值、参考值状态、参考值来源、参考 tour 校验和、所属 suite 及用途。

参考值状态至少分为 `proven_optimum`、`best_known`、`unknown`。参考值属于评价元数据；一般优化器不能读取它来改变搜索策略。最优值提前停止由平台控制。TSPLIB 官方分别提供数据与解值入口，可作为溯源起点。[TSPLIB 官方页面](https://comopt.ifi.uni-heidelberg.de/software/TSPLIB95/)

| 层级 | 拟选数据 | 用途及约束 |
| --- | --- | --- |
| 正确性 | 人工三角形、正方形、取整边界、可穷举的小实例 | 手工或独立穷举得到真值，验证闭合边与距离 |
| Smoke / 开发 | 小型 EUC_2D；`eil51`、`kroA100` 可作为候选 | 名称、类型和参考值需入库核验，不冒充正式五实例 |
| 主实验 | 前期材料中的五个 TSPLIB 实例，约 262–318 城市 | 必须恢复准确名单并冻结；现有材料仅明确展示 `lin318` |
| 扩展 | 不同规模与结构的独立实例，如早期文档提出的 `pcb442`、`pr1002` 候选 | 检查类型及计算资源后建立独立 suite，不混入主实验 |

五个正式实例的完整名单和参考值目前未在已检查材料中明确给出，不以城市规模推测补齐。名单未冻结时可以完成平台开发和 pilot，但不能宣称复现了原研究。TSPLIB 文件的维数是固有属性，不能像合成函数一样任意组合“实例 × 维数”。

## 5. 公共算法协议与受控变量

### 5.1 职责与数据流

```text
ExperimentSpec + InstanceManifest
               ↓ 校验、展开任务
RunSpec → Runner → Algorithm（公共稳态框架 / 外部适配器）
                      ↓ 请求求值
               EvaluationContext → TSPProblem
                      ↓ 统一状态与事件
                  Observer → 原始日志 → Analysis → 表格 / 图
```

建议协议如下，名称与签名是设计约定，不代表已有 API：

| 接口 | 契约 |
| --- | --- |
| `Problem.validate(tour)` | 验证长度、范围、无重复；非法解报告错误，不自动修复 |
| `EvaluationContext.evaluate(tour, phase)` | 先检查预算，再求值、计数、更新 incumbent 并发出事件 |
| `Algorithm.run(context, config, rngs, observer)` | 仅通过授权求值接口取得目标值；返回终止状态和种群摘要 |
| `Selection.select(population, rng)` | 返回个体身份；重复基因型仍是不同个体 |
| `Crossover.cross(p1, p2, rng)` | 不修改父代，只返回一个合法子代及可选诊断信息 |
| `Mutation.apply(child, rng)` | 位移语义固定；变异触发由公共框架管理 |
| `Replacement.update(population, child, rng)` | 执行固定替换规则并返回替换事件 |
| `Observer.on_event(event)` | 不修改搜索状态，不消耗算法随机流 |

TSP 距离矩阵在当前研究中属于算法可使用的实例结构；允许局部搜索利用距离，但所有用于搜索决策的候选目标比较必须进入预算协议。这样的平台属于可审计的组合优化基准系统，不声称强制实现了完全黑箱访问隔离。

### 5.2 首轮主实验冻结配置

| 项目 | 配置与精确定义 |
| --- | --- |
| 模型 | `(μ+1)` 稳态 GA，`μ=200` |
| 初始化 | 独立均匀随机排列；允许重复，不附加贪心初始化或去重 |
| Parent 1 | 逆向锦标赛 `k=2`；建议候选有放回抽样，长度最大者胜出，候选平局随机打破 |
| Parent 2 | RPS：从完整种群均匀有放回抽样，允许与 Parent 1 为同一个体 |
| 交叉 | PMX/OX/ERX/SAX，概率 1，每轮生成一个子代 |
| 变异 | 单城市位移，概率 0.05；从有序 `i≠j` 均匀抽样，`j` 明确定义为插入后最终位置 |
| 局部搜索 | 关闭 |
| 替换 | 在 `P∪{child}` 中删除长度最大个体；建议在全部最差个体中均匀抽取，包含子代 |
| 主预算 | 500,000 次后代求值，初始化另计 |
| 重复 | 每实例每算子 30 次，建议主实验 seed 为 1000–1029 |
| 提前停止 | 预算耗尽，或达到已证明最优值；记录准确首次命中位置 |

候选抽样、并列处理和插入位置是本计划补齐的建议语义，正式实施前应与算法负责人一起冻结版本。不得将本建议描述成前期文献已经明确采用的规则。尤其是替换平局会影响中性漂移和多样性，所有交叉必须使用完全相同规则。

### 5.3 算子接入的关键细节

- PMX/OX：冻结切点分布、区间开闭、父代角色及仅生成一个子代的规则，不允许生成两个子代后择优而只计一次。
- ERX：当前文档描述了优先共享边的变体；其优先级、起点、最小邻接表规则、随机平局与无邻居回退必须进入 `variant_id`。闭合末边单独检查，不能声称所有最终边都必然继承父代。
- SAX：使用 `D=1−|E(P1)∩E(P2)|/n`，抽取 `u∈[0,1)`，当 `u<D` 时委派 ERX，否则 OX。记录 `D`、委派结果及其成本。D 的计算不属于目标求值，但属于算法时间。
- 禁止让观测器为“交叉后、变异前”的子代额外求值却不计预算。可免费记录结构指标；若研究需要中间目标值，应开启独立诊断协议并明确其计算成本。
- `random_search` 用于端到端校验，`mutation_only` 用于后续消融；两者不自动扩充四算子的主比较集合。

以后实现 SPS 时，区分“两个父代个体身份不同”与“锦标赛内部无放回”，二者不是同一个参数。层内逆向选择涉及后代只能替换其父代等变化，必须独立注册算法变体，不能当作单纯 Parent-1 选择替换。

## 6. 预算、公平性与停止语义

### 6.1 权威计数器

| 字段 | 含义 |
| --- | --- |
| `initial_evaluations` | 初始化中完成的目标求值 |
| `offspring_evaluations` | 主框架提交的子代目标求值 |
| `local_search_evaluations` | 局部搜索实际检查的候选目标值，包含 delta 比较 |
| `total_evaluations` | 上述三项之和 |
| `full_objective_calls` / `delta_calls` | 实际完整求和与增量计算次数，用于成本审计 |
| `iterations` | 稳态迭代数；不等同于总求值数 |
| `wall_time` / `process_cpu_time` | 运行时间；分别记录加载和预处理时间 |

当前选型文档的 500,000 是后代求值预算。无提前停止且无局部搜索时，应有 `initial_evaluations=200`、`offspring_evaluations=500000`、`total_evaluations=500200`。图表必须标明横轴口径，同时保存全部计数器。未来采用总预算的实验使用不同 `budget_kind`，禁止暗中互换。

重复解也按一次逻辑求值计费，不能因为缓存命中而获得额外搜索机会。第一版默认关闭目标缓存；以后开启时分别记录逻辑次数、实际计算和缓存命中。同一局部搜索候选用 delta 得到目标值后被接受，不再按新候选重复计费；验证性完整重算单独登记 `audit_objective_calls`，不把它伪装成搜索收益。

求值入口在操作前检查预算；预算为零、恰好耗尽、初始化预算不足均有明确行为。非法排列终止该 run 并保留故障信息，不重采样掩盖缺陷。不完整初始化不进入进化阶段。

### 6.2 局部搜索扩展

2-opt 扩展必须先建立单独协议：每个实际比较的邻居计一次候选评价，即使只用四条边计算 delta。建议以总候选评价预算为主，辅以同机时间结果；不把 O(1) delta 计算和 O(n) 完整求和宣称为相同实际成本。

冻结 best/first improvement、扫描顺序、是否扫至局部最优、每子代上限及预算在扫描中耗尽时的处理。对 best improvement，建议只在完成一轮扫描后实施最佳移动；中断时保留已评估过的最好 tour 作为全局 incumbent，并明确其可能尚未进入种群。所有被评估候选都参与全局最优和命中时间更新，种群最优另设字段。

只对已证明最优的参考值允许“达到最优”停止。达到 best-known 只能标记为达到参考目标，不能宣称全局最优。时间上限或进程中断属于不同终止原因，不能直接当作完成固定预算实验。

## 7. 随机性与运行复现

1. 固定 `master_seed`、实例身份与重复编号，派生初始化流；四种交叉共享同一初始种群，并记录其哈希。
2. 分离选择、交叉、SAX 委派、变异、替换和诊断采样的 RNG 流，记录 RNG 算法与版本。
3. 使用稳定的种子派生方法及显式 `seed_schema_version`；不使用进程相关的语言默认哈希，也不把 worker 编号或任务调度顺序纳入种子。
4. 如需更严格的公共随机数设计，以“实例、重复、迭代、用途”派生子流；否则仅宣称配对初始化，不声称整条轨迹逐步使用相同随机事件。
5. 分析 bootstrap 使用独立分析 seed；pilot、调试与正式运行使用不同的重复集合。

每次运行记录代码 commit、dirty 状态及补丁/源码快照哈希、依赖锁文件、内核版本、操作系统、CPU、线程设置、配置哈希、实例哈希、协议版本和启动参数。主结果使用可归档的代码快照。固定环境下要求搜索轨迹与逻辑结果一致；时间戳、wall time 和资源测量不要求逐字节一致。

## 8. 日志与实验产物

### 8.1 每次运行的产物

```text
results/<experiment_id>/
  experiment.json             # 冻结的完整实验定义与实例清单
  task_manifest.json          # 预期运行集合及身份
  runs/<run_id>/<attempt_id>/
    manifest.json             # 输入、环境、版本与种子
    improvements.csv          # 每次严格改进及其精确预算位置
    checkpoints.csv           # 固定预算位置的状态摘要
    operator_summary.csv      # 分区间聚合的机制统计
    summary.json              # 最终结果、计数、状态和终止原因
    best_tour.json             # 最好回路、原始城市编号与复核长度
    error.json                # 失败时保存，不覆盖历史 attempt
  analysis/<analysis_id>/      # 脚本版本、参数、表格和图
```

`run_id` 由规范化配置、协议/实现版本、实例和重复编号稳定生成；重试生成新的 `attempt_id`。汇总按 run 身份选择预先规定的有效 attempt，保留重试历史，不能择优选取随机结果。

### 8.2 必要字段与触发规则

日志共同携带 schema 版本、run 身份、事件序号、阶段、迭代和各类预算计数；数值缺失使用 `null` 或规定的缺失编码，不用 0 冒充。

- 静态信息：算法/算子变体、全部显式与默认参数、种群规模、停止条件、参考值状态。
- 改进事件：当前已评估最好值、tour 哈希、命中位置与时间；每次严格改进均记录，不能仅依赖稀疏 checkpoint 重建命中时间。
- Checkpoint：初始化结束、预声明的对数/固定预算点以及终止点；记录全局最好值、种群最优/均值、边多样性、重复比例和累计成本。
- 算子信息：调用次数、父代差异分布、委派比例、结构保留指标；完整逐子代事件仅用于小型诊断运行，正式运行默认区间聚合。
- 终止：`budget_exhausted`、`optimum_reached`、`time_limit`、`failed`、`interrupted` 等；保留已用预算与失败阶段。

第一版采用 JSON 元数据和 CSV 数值表；大规模时可增加 Parquet 派生副本。观测成本进入时间统计，详细性能剖析采用单独实验。记录关闭/开启日志的 pilot 开销，必要时降低结构指标采样频率；不得减少精确改进与终止事件来掩盖目标命中。

文件按单 run 独立写入，完成后原子提交完成标记。批处理恢复首先以完整性校验跳过成功任务并重新运行失败任务；精确断点续跑作为后续功能，只有保存种群、所有 RNG、预算、算法状态和日志偏移且验证轨迹一致后才能启用。

## 9. 指标定义与学术分析

### 9.1 质量与运行时间

令 `b_r(t)` 为运行 r 在预算 t 前找到的最短长度，参考值为 `f_ref>0`：

\[
g_r(t)=\frac{b_r(t)-f_{ref}}{f_{ref}},\qquad g_r^{\%}(t)=100g_r(t).
\]

数据分别命名 `gap_ratio`、`gap_percent`，论文表头必须注明单位。对 best-known 使用“相对参考值差距”，允许负值；不能截断成 0。低于已证明最优值则触发实例或求值错误调查。

主要终点为固定后代预算的最终 `gap_ratio`；次要终点为命中、收敛和时间。报告均值、标准差、中位数、四分位范围和置信区间，而非只报告最优一次。预定义目标如 `{0.1, 0.01, 0.001, 0}` 为比例，其中 `0.001=0.1%`；零目标的最优命中解释仅适用于 proven optimum。

首次命中 `T_r(ε)=inf{t:g_r(t)≤ε}`。未命中属于右删失，不赋予伪造的成功时间。固定预算 B 下，同一实例、同一目标可报告

\[
ERT(\varepsilon)=\frac{\sum_{r=1}^{R}\min(T_r(\varepsilon),B)}{\sum_{r=1}^{R}\mathbf{1}[T_r(\varepsilon)\le B]}.
\]

该式用于每个失败运行确实用完 B 的场景；零成功时报告不可估计/无穷，并同时列出成功率。崩溃或外部超时不作为正常预算删失代入。提前达到 proven optimum 的运行可在固定预算质量图中前向延续最优值至 B，但不能补造实际运行时间或种群多样性轨迹。

ECDF 对预先声明的实例、目标和重复集合等权或按明确方案加权；失败项留在分母，不因成功多而得到更多权重。不同城市规模的相同 FE 不代表相同时间，必须分层解释并辅以 wall time。

### 9.2 结构与机制指标

父代边差异和种群平均边差异定义为

\[
D(P_1,P_2)=1-\frac{|E(P_1)\cap E(P_2)|}{n},\qquad
\overline D(P)=\frac{1}{\binom{\mu}{2}}\sum_{i<j}D(P_i,P_j).
\]

可用边在种群中的出现次数 `c_e` 精确计算

\[
\overline D(P)=1-\frac{\sum_e\binom{c_e}{2}}{n\binom{\mu}{2}}.
\]

该式适用于 n≥3 的合法对称回路、μ≥2；μ<2 记缺失。替换时更新受影响边的计数，避免每个检查点进行全种群两两比较。若采用抽样估计，必须与精确值区分，并使用独立诊断随机流。

交叉后、变异前的子代 C 记录：

- 边保留率：`|E(C)∩(E(P1)∪E(P2))|/n`。
- 位置保留率：`(1/n) Σ_i 1[C_i=P1_i 或 C_i=P2_i]`；只在声明的线性表示下解释。
- 相同父代身份比例、相同边集父代比例、子代与父代边集相同比例。
- SAX：D 的分布、ERX/OX 委派比例及分区间结构统计；检查实际 ERX 比例是否与对应 D 的平均值相符。

相关性不直接证明因果。父代 D 是搜索过程产生的变量，不能仅凭“D 大时 ERX 效果好”证明 SAX 的因果机制；应结合固定随机混合消融。

### 9.3 统计协议

1. 正式运行前冻结主要终点、比较集合、显著性水平（建议 0.05）、多重比较族与异常处理；不按最终结果选择预算点。
2. 同实例下按重复编号和相同初始种群形成配对块。两算法比较报告配对 gap 差值、效应量和配对 bootstrap 区间；可采用 Wilcoxon signed-rank，检查差值对称性及大量零差情形，必要时采用符号检验等预声明替代方案。
3. 多算法同实例的总体比较可用以重复为块的 Friedman 检验；后续配对检验采用 Holm 校正，说明每个检验族的边界。
4. 跨实例总体比较以实例为独立块，例如对每实例中位数排序后进行 Friedman 分析。不能把同实例的 30 次运行当作 30 个独立问题，或直接混合所有运行做无分层检验。
5. 主集合只有五实例，跨实例推断能力有限。重点报告逐实例效果及一致性；广泛泛化结论需扩充独立实例集。若采用层级 bootstrap，先抽实例、再抽内部配对重复，并说明小样本限制。
6. 交互实验使用按实例/重复分块的差中差或预声明模型，不以“一个显著、另一个不显著”代替交互检验。
7. 崩溃、非法 tour、日志缺失保留在运行清单并报告。正式分析发布前按固定规则完成重试或解释缺失，不静默删除失败，也不把失败当作最差 gap 掩盖工程问题。

图表至少包含逐实例最终 gap 分布、中位数收敛曲线、目标命中曲线、边多样性轨迹、结构保留比较与 SAX 委派轨迹。图中的范围须说明是四分位范围还是置信区间。极小/零 gap 的对数显示规则预先声明。

## 10. 分阶段实验矩阵与资源估算

| 阶段 | 实验设计 | 目的 |
| --- | --- | --- |
| Smoke | 人工实例或 1 个小实例，极小预算，固定 seed | 验证完整输入—运行—日志—分析链 |
| Pilot | 1–2 个开发实例 × 四交叉 × 5 个独立 pilot seed × 100,000 后代评价 | 检查正确性、日志量、吞吐与资源 |
| 主实验 | 冻结的 5 实例 × 四交叉 × 30 seed × 500,000 后代评价 | RQ1，共 600 run |
| SAX 消融 | 同实例与 seed，增加固定概率 OX/ERX 混合，如 `p(ERX)=0.5` | RQ2；主要参数预先固定 |
| 选择压力验证 | 四交叉分别配均匀、逆向 k=2；必要时增加正向 k=2 | RQ3；区分复用的主结果与新增结果 |
| 稳健性 | 单独增加 SPS、2-opt、规模或种群规模因素 | RQ4；避免一次展开全部因子 |

固定概率混合若进一步匹配 SAX 平均委派率，只能用独立开发数据确定概率，不能利用正式测试轨迹反向调参。比较套件可含无交叉基线，但需单独定义新的比较族。

主实验完整预算为 `600×500000=300,000,000` 次后代求值；初始化另有 `600×200=120,000` 次。该规模使得“先 profile、再决定优化实现”是实际需要。不能在没有吞吐测量时承诺一天完成。

Pilot 分实例/算法记录每 run 耗时、峰值内存、日志字节数、日志额外成本。预计总 CPU 时间为所有计划 run 耗时之和，wall time 还取决于并发、负载和 I/O；以分层 pilot 外推并报告余量。距离矩阵内存约为 `n²×每权重字节数`，并发数应受每 worker 内存约束。

并行单位为独立 run，默认每 run 单线程；避免数值库隐式线程过量。任务执行顺序随机交错不同算法，减少机器负载时间趋势。时间性能实验单独固定硬件、线程和负载条件，不能直接使用资源争抢下的批处理 wall time 宣称算法更快。

## 11. 平台测试与验收

| 层级 | 验证内容 | 验收标准 |
| --- | --- | --- |
| 问题正确性 | 人工真值、TSPLIB 取整、闭合边、参考 tour | 完整求值精确一致；非法/不支持实例明确失败 |
| 表示性质 | 旋转、反向、重标号及对应距离重排 | 目标和边差异按数学性质保持一致；不要求位置算子逐路径不变 |
| 算子性质 | 固定切点例子、随机合法父代、相同/反向父代 | 子代合法、父代未修改、固定 RNG 结果可重放 |
| SAX | D=0、D=1 可构造情形、阈值边界及委派 | 委派与规定一致，子算子契约保持 |
| 预算 | 初始化、重复解、最后一次评价、提前最优、2-opt 中断 | 不超预算，计数恒等式成立，停止原因正确 |
| 稳态不变量 | 替换前后及中性平局 | 种群大小不变，精英最优不恶化，既定平局规则一致 |
| 复现 | 相同环境重复执行、串并行切换 | 排除时间字段后，结果和改进轨迹一致 |
| 观测独立性 | 开关诊断或改变采样频率 | 搜索轨迹不变，时间差异单独记录 |
| 分析正确性 | 手工构造成功/失败/零差/缺失轨迹 | gap 单位、命中、ERT、聚合与校正结果可手工核对 |
| 运行可靠性 | worker 中断、重复任务、损坏输出 | 不把不完整 run 标为成功，不覆盖原 attempt |

性质测试用于研究结果可信度，不以代码覆盖率作为唯一标准。优化后的 delta 与独立完整求和做差分校验；边频数多样性与小种群两两计算交叉验证。正式数据发布前抽样重算 best tour，所有结果必须能关联到完整配置、实例和代码版本。

## 12. 实施里程碑与完成定义

以下为依赖顺序及建议工作量，不是已经完成的开发排期。首周目标只限最小可复现闭环，完整研究平台分阶段交付。

| 里程碑 | 建议工作量 | 交付物与退出条件 |
| --- | --- | --- |
| M0 协议冻结 | 1–2 工作日 | 问题、算子语义、预算、schema、实例来源和未决项登记；可先冻结开发 suite |
| M1 问题与预算内核 | 2–3 工作日 | 解析、距离、求值台账、人工真值测试通过 |
| M2 最小运行闭环 | 2–3 工作日 | 公共 GA + OX/简单基线 + 单 run 日志；同 seed 重放一致；首周优先验收目标 |
| M3 四算子与机制观测 | 3–5 工作日 | PMX/ERX/SAX 接入；性质、结构指标、观测独立性测试通过 |
| M4 批处理与分析 | 2–4 工作日 | 配置校验、任务清单、并行、失败恢复、统计和图表可重建 |
| M5 Pilot 与正式冻结 | 1–2 工作日加计算时间 | pilot 报告、资源估算、正式五实例及协议全部冻结 |
| M6 主实验与归档 | 按 pilot 估算 | 预期 600 run 全部有可追踪终态；主分析、数据字典和复现说明完整 |
| M7 扩展 | 单独评估 | SAX 消融与选择压力交互优先；局部搜索和兼容导出随后 |

M2 的最低可交付闭环是：“一个实例、一份配置、一个 seed → 一次有效运行 → 一份可复算结果 → 再运行得到相同逻辑轨迹”。M6 的完成不以任何算法获胜为条件，而以数据完整、比较公正和分析可重建为条件。

未来 CLI 至少覆盖配置/实例校验、单次运行、批量计划预览、批量运行、失败清单、结果汇总及报告生成。`dry-run` 应展示确切 run 数、预算和输出位置；正式执行前即可发现非法参数组合与遗漏实例。

| 项目 | 当前状态 | 实施时的处理 |
